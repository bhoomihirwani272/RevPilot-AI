# SalesVision AI

### AI-Powered Sales Management System \| Internship Project: AgentAI-035

SalesVision AI is a sales analytics and management application built to
help sales teams review performance, monitor opportunities, understand
deal risk, and explore revenue trends from structured sales data.

The application provides role-oriented workspaces for a Chief Revenue
Officer (CRO), Sales Manager, and Sales Representative. It combines data
processing, machine-learning predictions, forecasting outputs, and
interactive visualizations in one Streamlit dashboard.

> **Project status:** The dashboard and its core analytics pages have
> been developed. Model performance and end-to-end behaviour should be
> validated against the latest project run before using results in a
> formal business or internship evaluation.

## Key Features

-   **Role-oriented dashboard:** Separate overview experiences for CROs,
    Sales Managers, and Sales Representatives.
-   **Representative performance:** Review sales results, win rates, and
    representative scorecards.
-   **Territory analysis:** Compare revenue and performance across
    territories.
-   **Quota tracking:** Examine actual sales, assigned quotas, and
    attainment.
-   **Pipeline monitoring:** Review opportunity stages, pipeline value,
    and deal-health information.
-   **Deal-risk prediction:** Use the trained XGBoost model to support
    risk assessment for open opportunities.
-   **Revenue forecasting:** Display forecast results generated by the
    project's forecasting workflow.
-   **Commission reporting:** Review commission information from
    generated reports.
-   **AI coaching reports:** Read and download representative coaching
    reports when available.
-   **Sales assistant:** Ask questions about sales data through the
    assistant module.
-   **Reports and downloads:** Access generated CSV reports from the
    dashboard.
-   **System status:** Check whether expected reports and model files
    are present.

## Application Workspaces

### 1. CRO --- Executive Command Center

Provides a company-level view of sales performance, including total
sales, open pipeline value, quota attainment, average win rate, revenue
contribution, territory performance, and deal-risk distribution.

### 2. Sales Manager --- Team Performance Workspace

Helps managers review team performance, compare representatives, monitor
quota progress, and identify areas that may need coaching.

### 3. Sales Representative --- Individual Performance

Provides an individual view of sales performance, including won revenue,
win rate, quota attainment, and available coaching information.

The workspace selector changes the dashboard view for demonstration
purposes. It is **not** a production authentication or authorization
system.

## Machine Learning and Analytics

### XGBoost Win Prediction

The project includes an XGBoost classifier intended to learn from
historical closed opportunities and estimate win outcomes. The training
workflow is located at:

`src/ml_models/train_xgboost.py`

The trained model and its feature list are saved to:

-   `models/xgb_win_model.joblib`
-   `models/model_features.json`

The model should be evaluated on a held-out test set. Useful evaluation
measures include accuracy, precision, recall, F1-score, ROC-AUC (when
applicable), and a confusion matrix. Do not interpret training-set
performance as an estimate of performance on unseen opportunities.

### Open Deal Risk Prediction

The dashboard can call the prediction function in:

`src/genai/deal_predictor.py`

When the module and model files are available, the AI Sales Assistant
page provides an **Open deal risk snapshot** to load predictions for
open opportunities. The risk categories and their thresholds should be
documented alongside the implementation and verified against the code.

### Revenue Forecasting

The Revenue Forecast page reads:

`output/forecast_results.csv`

The dashboard expects a date column (commonly `ds`) and a forecast-value
column (commonly `yhat`). Lower and upper forecast bounds may also be
displayed when available.

### Sales Assistant and Coaching

-   `src/genai/sales_agent.py` provides the sales-question answering
    function used by the dashboard, if its imports are available.
-   Coaching reports are read from `output/coaching_*.txt`.

The actual assistant behaviour depends on the implementation and
configuration in those modules. Do not describe it as a live
generative-AI service unless the required model/API integration is
configured and working.

## Installation and Setup

### 1. Get the project

If the repository is hosted on GitHub:

``` bash
git clone <YOUR_GITHUB_REPOSITORY_URL>
cd SalesManagementSystem
```

Alternatively, open the existing project folder in Visual Studio Code.

### 2. Create a virtual environment

**Windows PowerShell:**

``` powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

If PowerShell blocks activation, use an appropriate execution-policy
setting for your machine or activate the environment from Command
Prompt:

``` cmd
venv\Scripts\activate.bat
```

### 3. Install dependencies

``` bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If `requirements.txt` is not present, create it from the verified
working environment:

``` bash
pip freeze > requirements.txt
```

Review the generated file before committing it, and avoid including
unrelated packages from the environment.

## Run the Application

From the project root, with the virtual environment activated:

``` bash
streamlit run app.py
```

Streamlit will print a local address in the terminal. Open that address
in a browser to use the dashboard.

To stop the application, press `Ctrl + C` in the terminal.

## Model Training

To train and save the XGBoost model, run:

``` bash
python src/ml_models/train_xgboost.py
```

After a successful run, verify that these files exist:

``` text
models/xgb_win_model.joblib
models/model_features.json
```

Review the terminal output and retain the evaluation report from the
held-out test data. If the training script changes, retrain the model
and re-check the prediction workflow.

## Data and Model Notes

-   Use authorized data only. Do not commit confidential customer,
    employee, or company information to a public repository.
-   If the project uses synthetic or demonstration data, clearly label
    it as such in presentations and reports.
-   Keep training data separate from test data.
-   Perform preprocessing and feature selection using training data only
    where applicable, to avoid data leakage.
-   Check for class imbalance and use suitable evaluation metrics.
-   A prediction for an open opportunity is not a confirmed outcome. Its
    true performance can only be measured after the opportunity outcome
    is known.
-   Record the dataset version, feature list, train/test split, random
    seed, and model evaluation results for reproducibility.

## Limitations

-   Dashboard figures depend on the latest generated CSV reports; stale
    reports can produce stale results.
-   The quality of predictions depends on the size, quality,
    representativeness, and labelling of the historical dataset.
-   Forecast values are estimates and should be compared with actual
    results.
-   The workspace selector is a demonstration feature, not secure
    role-based access control.
-   Optional AI features may require additional configuration and may
    not be available in every environment.
-   This project is intended as an academic/internship demonstration and
    should not be treated as a production sales or financial decision
    system without further validation, security, and operational
    testing.
